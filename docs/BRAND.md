## 0. ブランドの核 — YOU + ME → WE

> **違うから、知りたくなる。**
> **知るから、わかり合える。**
> **そして、新しい「私たち」が生まれる。**

このプロダクトは「カップル向け質問アプリ」でも「相性診断」でもありません。
**二人の違いから、新しいWEをつくる Relationship OS** です。

```
YOU          ME           EXCHANGE      UNDERSTAND      WE
自分を知る → 相手を知る → 価値観を交換 → なぜ違うのか →  二人だけの答え
```

### 0.1 判断基準

機能・UI・コピー・AI・ロゴのすべてを、この一文で判断します。

> **YOUかMEのどちらかに合わせるのではなく、二人の間に新しいWEを生む。**

- 片方に寄せる提案、どちらが正しいかの示唆は、**この基準に反するので実装しない**
- 「違い」を欠点・リスク・課題として描かない。**違いは知り合う入口**として描く
- 二人が作ったものは `NEW WE` として残す。積み上がるのはスコアではなく**私たち**

### 0.2 NEW WE — このプロダクト最大の資産

相性スコアの代わりに `NEW WE` を育てます。保存されるのは4種類だけです。

| 種類 | 中身 | 生まれる場所 |
| --- | --- | --- |
| `discovery` | 新しく知った相手の価値観 | 同時公開のあと |
| `answer` | 二人で作った**第三の答え** | 同時公開のあと（AIが下書き） |
| `promise` | 二人で決めた約束 | 約束・整える（Repair） |
| `future` | 二人で見つけた未来像 | 未来 |

**第三の答え**とは、YOUの答えでもMEの答えでもない、二人だけの答えのことです。
AIは「価値観が違います」で終わってはいけません。なぜそう思うのか・何を失いたくないのか・
何が不安なのかを両側から整理し、**二人が受け取って、直して、自分たちの言葉にできる下書き**を出します。
確定するのは常に二人であり、AIではありません。

### 0.3 AIは裁判官ではなく、愛の通訳者

`docs/BRAND.md` §6 の言葉のトーンに加えて、AIには次を禁じます（仕様 §4, §17, §24）。

- どちらが正しいかを判定する／相性を点数化する
- 結婚すべき・別れるべきと断定する／関係の継続を強制する
- 違いを「悪いこと」として扱う／片方の意見に誘導する／罪悪感を与える

**前提**: 違いは問題ではない。**違いを理解しないこと**が問題になる。

## 1. ロゴが決めていること

ブランドマークは、**黄金比で組まれた二つの円**と、その上に置かれた**二つの頭**、
そして中央に生まれる**レンズ形（vesica）**でできています。

二つの円は「二人」。頭は「それぞれが独立した人であること」。
中央のレンズが `WE` ——**二人が重なったところにだけ生まれるもの**です。

### 1.1 幾何 — すべて φ から導かれる

出典は `src/config/mark-geometry.json`。マークもPWAアイコンもこの1ファイルから描かれます。

| 要素 | 式 | 値 |
| --- | --- | --- |
| 円の半径 `R` | 基準 | `438` |
| 中心間距離 | `2R / φ` | `541.3978` |
| 重なりの幅 | `2R / φ²` | `334.6022` |
| 頭の直径 | `R / φ²` | `167.3011` |
| 線幅 | `R / φ⁵` | `39.4944` |
| 頭と円の間隔 | `R / φ⁴` | `63.9033` |
| 全体の縦横比 | `(2R + d) / 2R` | **`φ` ちょうど** |

**この数値を目分量で変えないこと。** 変えるならφから導き直してください。

### 1.2 色 — 5段のシームレスグラデーション

一本のグラデーションが**両方の円とレンズを貫きます**（円ごとに別のグラデーションを
持たせてはいけません。それでは「二人が連続している」ことが表現できません）。

| 位置 | 値 | 色相 |
| --- | --- | --- |
| 0% | `#36A7F4` | 204° |
| 30% | `#6F8EF2` | 226° |
| 50% | `#AC75E6` | **269°** |
| 70% | `#D765CC` | 306° |
| 100% | `#F74699` | 332° |

204° と 332° の中点は **268.1°**。中央の実測色相は **269.2°**。
差はわずか **1.1°** ——「二人の心が中央で混ざり合う」は、比喩ではなく
**このロゴの色相構造そのもの**です。

頭だけはグラデーションを使わず、**単色**です（`#36A7F4` と `#F74699`）。
一人ひとりは混ざりものではない、という意味を持たせています。

**このプロダクトの全UIは、この色相ライン上に置く。**

```
  204° ──────────── 269° ──────────── 332°
   YOU              WE               ME
  blue            purple            pink
  一人            二人が生むもの      もう一人
```

**青がピンクになるのでも、ピンクが青になるのでもありません。**
二人とも自分を失わず、違うまま重なり、その中央に新しいWEが生まれる。
これがロゴの意味であり、そのままプロダクトの意味です。

## 2. 色の三層構造

色は「役割」で3つの層に分かれます。**層をまたいだ使い方は禁止です。**

### 層1: アイデンティティ（ロゴ実測値そのまま）

```
--brand-blue          #36A7F4   0%
--brand-blue-violet   #6F8EF2   30%
--brand-purple        #AC75E6   50%
--brand-magenta       #D765CC   70%
--brand-pink          #F74699   100%
```

- **使ってよい場所**: ロゴ、大きな装飾面、グラデーションの構成色、区切り罫、ダークテーマ上のアクセント、
  そして **`--on-blend`（濃紺）の文字を乗せる面**（主要ボタンの `.bg-blend`、入口の性別選択 `bg-brand-blue` / `bg-brand-pink`）
- **絶対に使わない場所**: 明るい背景の上のテキスト、アイコン、細い線、
  **白文字を乗せた面**（白文字との比は 2.6〜3.3:1 しかなく、WCAG AAを満たさないため）

### 層2: インタラクティブ（同一色相・可読な明度）

| トークン | Light | Dark | 用途 |
| --- | --- | --- | --- |
| `--primary` | `#8340C4` | `#C79BEF` | 二人の共有物を指すテキスト・アイコン（270°） |
| `--person-a` | `#0E6AC8` | `#8AC9FB` | 一人目の識別色（210°・テキスト可） |
| `--person-b` | `#C8005C` | `#FB92BC` | 二人目の識別色（332°・テキスト可） |
| `--on-blend` | `#26123C` | `#26123C` | **ロゴ色の面に乗せる文字色**（両テーマ共通） |

> `--on-blend` がライト／ダークで同じなのは、ロゴの色自体がテーマで変わらないため。
> マークが変わらない以上、その上に乗る文字も変わってはいけない。
>
> **この文字色は黒ではありません。** グラデーションの上に中性的な黒を置くと、
> 「後から載せた文字」に見えます。`--on-blend` は色相 269°・彩度54%の**深い紫**で、
> マークの中央とまったく同じ色相にあります。だから面と文字が同じ家族に見える。
> 白文字は使えません（新しいロゴ色に対しても 2.6〜3.3:1 しかありません）。

### 層3: 面（極薄のティント）

| トークン | Light | 用途 |
| --- | --- | --- |
| `--person-a-soft` | `#E9F3FF` | 一人目の回答カード |
| `--person-b-soft` | `#FFEEF3` | 二人目の回答カード |
| `--together-soft` | `#F4ECFB` | 二人の共有物（約束・Insight・記録） |

## 3. 中心原則 — 「誰の色か」で塗る

**このプロダクトでは、色は装飾ではなく“話者の帰属”を示す情報です。**

| 対象 | 色 |
| --- | --- |
| 自分（ログイン中の本人）に属するもの | `person-a` 系 |
| 相手に属するもの | `person-b` 系 |
| **二人で作ったもの**（同時公開された回答、AI Insight、二人の約束、Journey完了、ふたりページ） | **`primary` / ブレンド** |
| どちらのものでもない中立要素 | `surface` / `text-muted` |

> ⚠️ 個人の色（青・ピンク）を、二人の共有物に使ってはいけません。
> 逆に、片方だけの入力欄をブレンド色で塗ってもいけません。
> **色が嘘をつくと、このプロダクトの中核である「同時公開」の信頼が壊れます。**

### 3.1 入口の2色 — 登録時の性別選択

登録の入口だけは、**ロゴの2つの円をそのまま2つの選択肢**として見せます。

| 選択肢 | 塗り | 文字 |
| --- | --- | --- |
| 男性 | `bg-brand-blue`（左の円・左の頭 `#36A7F4`） | `text-on-blend` |
| 女性 | `bg-brand-pink`（右の円・右の頭 `#F74699`） | `text-on-blend` |
| その他・答えない | `bg-surface-muted` + `border` | `text-text` |

この2色は「男らしさ／女らしさ」の記号ではありません。
**ロゴの2つの円のうち、自分がどちらの円として登録するか**を選ぶ体験です。
だから選択肢は排他的な2択にせず、**第三の選択肢を必ず用意します**。

**そして、この対応をアプリ内部に持ち込むことは禁止です。**
ログイン後の色は、これまで通り常に「自分＝`person-a`（青）／相手＝`person-b`（ピンク）」であり、
**性別からは決まりません**。だから男性同士でも女性同士でも、
それぞれが「自分＝青／相手＝ピンク」という同じ体験を見ます。色は破綻しません。

> ⚠️ `gender` の値で `person-a` / `person-b` の色を出し分けてはいけません。
> `brand.test.ts` が同一行での同居を検出して落とします。
> 性別は、AIの助言・質問の出し分け・相性の判定にも一切使いません（仕様 §17, §24）。

## 4. グラデーションの使用規則

グラデーションは**意味のある瞬間にだけ**使います。乱用は禁止です。

| ユーティリティ | 定義 | 使ってよい場面 |
| --- | --- | --- |
| `.bg-blend` | **5段のシームレスグラデーション**（ロゴそのもの） | 主要ボタン、進捗バー、区切り罫、マーク |
| `bg-brand-blue` / `bg-brand-pink`（単色） | ロゴの円そのもの | **登録入口の性別選択のみ**。必ず `text-on-blend` |
| `.bg-wash` | a-soft → together-soft → b-soft | 同時公開パネル、ふたりページのヒーロー |
| `.text-blend` | person-a → primary → person-b（可読版） | **ワードマークと「二人の答えがそろいました」の見出しのみ** |
| `.rule-blend` | 2pxの罫 | 二人に属する見出しの下線 |

### 主要ボタンの質感 — 「二人がはじまる」瞬間

主要ボタンは、このプロダクトで**二人が一緒に何かを始める場所**です。
平らな色面ではなく、**押したくなる物体**として作ります。

| 要素 | 指定 | 理由 |
| --- | --- | --- |
| 文字 | `font-bold` + `tracking-[0.02em]` | 和文の細字（W3）は明るい面の上で痩せて見える。太さで確信を持たせる |
| 文字色 | `--on-blend`（深い紫。**黒ではない**） | 黒は「後から載せた文字」に見える。色相線上の紫なら面と同じ家族になる |
| 文字組み | `font-feature-settings: 'palt'` | 和文の字間を詰め、ボタン内の言葉を一語として見せる |
| グラデーション | `--gradient-blend` を等倍で | 面には**常にロゴの全域**（水色→紫→ピンク）が出ていること。一部だけを見せない |
| 動き | `animate-blend-drift`（12秒） | 色の上を**やわらかい光が横切る**。グラデーション自体は動かさない。点滅・高速化は禁止 |
| ホバー | わずかに明るく＋影を持ち上げる | 触れたことが分かる最小限。色相は変えない |
| 押下 | `active:scale-[0.985]` + 影を沈める | 物体として沈む。跳ねない（バウンス禁止） |
| 縁 | `inset 0 1px 0 rgb(255 255 255 / 0.45)` | 上端の光。厚みを1pxで示す |

**禁止**: 点滅、虹色、3秒未満の周期、押下時のバウンス、影の色を原色にすること。

### `.bg-blend` の上の文字は必ず `text-on-blend`

主要ボタンはロゴの水色→紫→ピンクをそのまま塗ります。この面は明るいため、
**白文字は使えません**（白との比は最良でも 3.3:1）。必ず `--on-blend`（深い紫）を乗せること。
この紫ならグラデーションのどの位置でも **5.0:1 以上**を確保でき（実測 5.10〜6.66:1）、
`brand.test.ts` が5つの停止色すべてで検証します。

`.text-blend`（文字のグラデーション）だけは別系統です。明るいロゴ色を文字にすると読めないため、
**同じ色相のまま明度を落とした可読版**（person-a → primary → person-b、最低 5.3:1）を使います。

**禁止**:
- 1画面に `.bg-blend` のボタンを2つ以上置かない（主要アクションは常に1つ）
- `bg-brand-*` の単色塗りを、登録入口の性別選択以外（コンテンツ、カード、ナビ）に使わない
- グラデーションの上に小さな文字を置かない（`.text-blend` の指定用途を除く）
- ロゴ以外の配色でグラデーションを作らない。`--gradient-*` 以外の混色・虹色は禁止（仕様 §20）

## 5. 形・余白・動き

- **角丸**: `--radius` 20px を基準（16〜24pxの範囲。仕様 §20）
  カード `rounded-card` / 小要素 `rounded-card-sm` / 大パネル `rounded-card-lg`
- **タップ領域**: 最小 44px（`min-h-11`）。例外なし
- **影**: `shadow-card` を基本。持ち上げは `shadow-lift` のみ。影に色を付ける場合は紫寄り（`rgb(83 49 110)`）
- **動き**: `animate-gentle-rise`（0.45s）が基本。待機中のみ `animate-lens-breathe`、
  主要ボタンのみ `animate-blend-drift`（12秒。速度を上げることは禁止）
  紙吹雪・バウンス・派手な演出は禁止。`prefers-reduced-motion` は全アニメーションで尊重
- **文字**: 和文は `font-feature-settings: 'palt'` を全体に適用。
  `antialiased` は使わない（明るい面の上で和文が痩せ、細い線のように見えるため）

## 6. 言葉のトーン

色と同じ規律を言葉にも適用します（仕様 §20, §24, §26）。

**使う言葉**: 一緒に話せた日 / 積み重ねた会話 / 見つけた共通点 / 伝えられた感謝 / 二人で決めた約束

**禁止する言葉**:
- 「連続記録が途切れます」など、罪悪感・脅しを含む表現
- 「相性◯点」「相性が低下しています」など、点数化・優劣の判定
- 「別れるべき」「絶対に結婚すべき」など、断定・強制
- 通知本文に争いの内容を書くこと
- 「彼氏／彼女」「旦那さん／奥さん」など、**性別を決めつける呼び方**
  （常に「パートナー」「二人」と呼ぶ。どの性別の組み合わせでも同じ言葉で届くように）

## 7. 禁止事項まとめ（チェックリスト）

コードレビューで必ず確認してください。

- [ ] ロゴ実測色（`#36A7F4` 〜 `#F74699`）を明るい背景のテキストに使っていない
- [ ] 生のカラーコードをコンポーネントに直書きしていない（必ずCSS変数経由）
- [ ] 個人の色と二人の色を取り違えていない
- [ ] 主要アクション（`.bg-blend`）が1画面に1つ
- [ ] `.bg-blend` の上の文字が `text-on-blend`（深い紫）になっている。白文字・黒文字は禁止
- [ ] `bg-brand-blue` / `bg-brand-pink` の面にも `text-on-blend` 以外の文字色を乗せていない
- [ ] 性別（`gender`）で `person-a` / `person-b` の色を出し分けていない（§3.1）
- [ ] 新しい色を足していない（足すなら本ファイルとテストを先に更新する）
- [ ] ライト／ダーク両方で 4.5:1（テキスト）／3:1（UI）を満たす
- [ ] ハートマークの乱用・ピンク一色のカップル感・子どもっぽい装飾になっていない（仕様 §20）

## 8. 変更手順

色やトーンを変えたい場合は、必ずこの順序で行ってください。

1. `docs/BRAND.md`（本ファイル）を更新する
2. `src/tests/unit/brand.test.ts` の期待値を更新する
3. `src/app/globals.css` のトークンを更新する
4. `pnpm test` と `pnpm test:e2e`（axeによるWCAG検査を含む）を通す

**逆順は禁止**です。CSSだけを書き換えると、テストが落ちて必ず気づけるようになっています。
本ファイルの表に書いた値も `brand.test.ts` が `globals.css` と突き合わせるので、
ドキュメントだけが古くなることもありません。

### ロゴそのものを差し替える場合

1. `docs/brand/` に新しい原本（SVG）を置く
2. `src/config/mark-geometry.json` の座標を、原本から導き直す（目分量禁止・φから導出）
3. `pnpm icons` でPWAアイコンを再生成する
4. `pnpm test:e2e` を通す — `src/tests/e2e/brand-mark.spec.ts` が、画面のマークと
   `docs/brand/logo-master.svg` を同じ大きさで描いて**1画素ずつ**比較します。
   ずれれば落ちます。

マークを描くコードは `src/components/shared/brand-mark.tsx` と
`scripts/generate-icons.mjs` の2箇所だけで、どちらも上の1ファイルから座標を読みます。
座標を手で書き写すことは禁止です（`brand.test.ts` が検出します）。
